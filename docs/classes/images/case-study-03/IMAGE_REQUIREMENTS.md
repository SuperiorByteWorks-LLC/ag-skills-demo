# Image Requirements: Case Study 1.03 - NASA Harvest

This document specifies image requirements for the NASA Harvest Satellite Data case study slides and supporting materials.

---

## General Requirements

**Format Specifications:**

- **Resolution:** 1920x1080 pixels (16:9 aspect ratio)
- **File format:** PNG (preferred) or high-quality JPG
- **File size:** <500KB per image (for web performance)
- **Color mode:** RGB
- **Usage context:** Slide presentations, web viewing

**Attribution Requirements:**

- All images must include source attribution
- Prefer public domain or Creative Commons licensed images
- NASA images are public domain and preferred for space/satellite content
- Document license and attribution for each image

## Image Usage Guidelines

### In Slide Deck (Class 01)

- Images should support key concepts, not distract from content
- Place attribution in small text at bottom corner of slide
- Ensure images are legible when projected
- Test visibility in both light and dark presentation modes

### In Case Study Document

- Images can be larger and more detailed
- Include full attribution directly below image
- Provide figure captions explaining significance
- Link to higher-resolution versions if available

### Accessibility Considerations

- Provide alt text descriptions for all images
- Ensure color contrasts meet WCAG AA standards
- Don't rely solely on color to convey information (use patterns/labels)
- Test image legibility for colorblind viewers

## Image Creation Workflow

### For Custom Images (Infographics, Maps)

1. Draft content based on case study data
2. Create in appropriate tool (Canva, Illustrator, QGIS, etc.)
3. Export at 1920x1080 resolution
4. Optimize file size (<500KB)
5. Document all data sources used
6. Save source files for future editing

### For Sourced Images (Photos, Satellite Imagery)

1. Search appropriate sources (NASA, ESA, Creative Commons)
2. Verify license allows educational use
3. Download highest quality available
4. Resize/crop to 1920x1080 if needed
5. Document source, date, license
6. Save original and processed versions

### For Screenshots (Apps, Interfaces)

1. Obtain permission if showing proprietary interfaces
2. Take screenshot at high resolution
3. Crop/annotate to highlight relevant features
4. Ensure no sensitive information visible
5. Document source and any permissions
